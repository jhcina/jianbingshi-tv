# 开源吸收决策：家庭桌面，少折腾

核对日期：2026-10-24。结论来自仓库源码、许可和指定 MFTR0 设备试验；列为候选不代表已经实现或完成授权核对。

## 我们要交付什么

让家人开电视后直接找到常用应用、看自己的照片；更新和待机以后仍然能用，失败时知道原因并能恢复。以归藏为底座，保持远距离清晰的黄色焦点与相纸图标。这个目标不要求把桌面改成影视聚合站。

## 读源码后需要改进的地方

- DpadTV `QrAddServer.kt` 是轻量文本接收服务：接收页关闭会停止服务，这点值得保留。但该文件没有短时配对令牌，绑定也未限制到选定私网地址；请求体按字符读取而 Content-Length 是字节，不能照搬成我们的照片上传服务。我们的候选应加短时配对、体积／数量限制、字节级读取、失败不覆盖原片、离开即关闭。本轮未实现上传。
- DpadTV `UpdateChecker.kt` 使用 Releases/latest，版本比较忽略预发布后缀。我们的公开发行仍是 preview，需明确稳定／预览通道、真实包身份和签名匹配；不能照搬后误报无更新或把预览当正式。本轮未实现更新中心。
- LibreTV `playback-recovery.ts` 区分网络与解码错误并限制重试，`host-gate.ts` 限制同主机并发，`proxy-handlers.ts` 引用逐跳地址检查。这些适合故障处理方法学习；浏览器 HLS 实现不能直接当成 Android MediaPlayer 修复，更不能修复另一个闭源 App。
- Aerial 同机型笔记与本机观察吻合：单独设置 HOME 角色不能阻止关屏清理。新候选只恢复自身 Home 服务，不引入账号同步、保持 ADB、屏保替换、按键过滤或主动切换其他前台应用。

## 最值得放大的差异

1. **装好后少折腾**：按机型检查、精确授权、关屏与重启分开验收、升级保留数据、关闭及恢复可理解。还未通过的情形明确标实验。
2. **自己的照片真的能长期用**：公开／私有分开、竖幅完整显示、看照片、下一步优先扫码导入、删除与备份恢复。手机配对与备份尚未实现。
3. **适合远距离观看的视觉**：固定图标槽位和文字起点、图标保持不透明、深浅底可辨认；不以电脑大图好看替代电视验收。

先稳住前两项主流程，再做可选应用指引与更新提示。暂不把影片检索、解码器、2 GB 播放缓存和后台服务器都塞进桌面；每项新依赖都必须证明会减少家庭使用负担。

## 实施边界

本轮没有联系维护者、上传第三方安装包、配置影视源、部署 LibreTV 或改动本项目公开许可证。已实现的 Aerial 参考部分见 NOTICE.md 与待机恢复说明；默认图标包仍为本地可选资源，人物及私人截图不发布。
